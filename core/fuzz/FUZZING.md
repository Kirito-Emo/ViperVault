# ViperVault Fuzzing Strategy

## Overview

ViperVault Core uses coverage-guided fuzzing to continuously test the
robustness of all attacker-controlled input boundaries.

Fuzzing complements unit tests and property tests by exploring large
input spaces containing malformed, truncated, mutated, and adversarial
data.

The fuzzing infrastructure is based on:

- **cargo-fuzz**
- **LLVM libFuzzer**
- **AddressSanitizer**
- Rust nightly toolchain

The goal is to ensure that all parsing and decoding code behaves safely
under arbitrary input.

---

# Security Goals

Fuzz targets must guarantee the following properties:

* No panics
* No aborts
* No memory safety violations
* No infinite loops
* No unbounded allocations
* No unexpected crashes

All failures must be handled through explicit error returns.

---

# Threat Model Coverage

Fuzzing targets the primary untrusted input boundaries in ViperVault.

## Vault Container Parsing

```sh
decode_vault_file
decode_signed_backup
```

These targets exercise parsing of attacker-controlled vault container
data, including:

- corrupted headers
- truncated payloads
- invalid storage modes
- oversized payload fields
- trailing data attacks

---

## OTP URI Parsing

```sh
parse_totp_otpauth_uri
import_interop_quarantine
otpauth_roundtrip
```

These targets validate parsing of OTPAuth URIs used during interoperability imports. \
They test resilience against malformed URIs and unexpected parameters.

---

## Encoding and Canonicalization

```sh
decode_base32_secret_strict
canonicalize_base32_for_export
```

These targets validate Base32 input normalization and decoding safety.

---

## Vault Operations

```sh
vault_codec_roundtrip
enable_duress_on_vault
```

These targets verify vault encode/decode logic and migration behaviour.

The migration target exercises:

- legacy vault decoding
- dual header construction
- envelope encryption
- duress vault creation

---

## Structure-aware fuzzing

ViperVault also uses structure-aware fuzz targets for selected semantic
flows.

These targets generate bounded protocol-shaped inputs via
`arbitrary::Arbitrary`.

They complement, but do not replace, raw byte-level fuzzing.

---

# Corpus Structure

```md
fuzz/
├── corpus_seed/
├── corpus/
├── corpus_min/
├── artifacts/
└── logs/
```

### corpus_seed

Curated high-value inputs manually maintained by developers.
> These inputs bootstrap fuzzing campaigns and are version-controlled

### corpus

Runtime corpus generated by fuzzing campaigns.
> This directory is not version-controlled

### corpus_min

Minimized corpus produced using `cargo fuzz cmin`. \
It retains coverage while removing redundant inputs.

### artifacts

Crash inputs produced by libFuzzer. \
Each artifact must be investigated immediately.

---

# Seed Promotion Policy

Inputs from `corpus_min` may be promoted to `corpus_seed` when they:

* exercise deep parser states
* represent realistic malformed structures
* improve coverage stability
* represent meaningful semantic cases

> Promoted seeds must be renamed using semantic filenames

---

# Crash Triage Process

If fuzzing produces an artifact:

1. Reproduce crash

```bash
cargo +nightly fuzz run <target> <artifact>
```

2. Minimize input

```bash
cargo +nightly fuzz tmin <target> <artifact>
```

3. Investigate root cause

4. Fix vulnerability

5. Add minimized input to `corpus_seed` as regression seed

---

# Heavy Targets

The following target is computationally expensive: `enable_duress_on_vault`.

It performs Argon2id key derivation with production parameters:

```sh
memory = 64 MiB
iterations = 3
lanes = 1
```

This drastically reduces iteration throughput and is expected. \
This target is therefore used in longer fuzz campaigns.

---

# Fuzz Campaign Workflow

Typical fuzz campaign:

1. run fuzz
2. inspect logs
3. minimize corpus
4. promote useful seeds
5. repeat

---

# Limitations

Fuzzing increases confidence in parser robustness but cannot prove
the absence of vulnerabilities.

Fuzzing should be combined with:

- unit tests
- property tests
- manual security review
- threat modeling
