# ViperVault Fuzzing

This directory contains fuzzing infrastructure for **ViperVault Core** using
[`cargo-fuzz`](https://github.com/rust-fuzz/cargo-fuzz) and LLVM libFuzzer.

The purpose of fuzzing in this project is to continuously validate that all
untrusted-input boundaries behave safely under arbitrary input streams.

In particular, fuzzing ensures that:

- no panics occur on attacker-controlled input
- no hangs or pathological parsing loops occur
- no memory safety violations are triggered
- serialization / deserialization boundaries behave robustly
- security invariants are preserved under malformed input

Fuzzing complements unit tests and property tests by exploring a very large
space of malformed or unexpected inputs.

---

# Fuzz Targets

The project currently includes the following fuzz targets.

## Container / Storage parsing

| Target                 | Purpose                                |
|------------------------|----------------------------------------|
| `decode_vault_file`    | Main vault container decoding boundary |
| `decode_signed_backup` | Signed backup container decoding       |

These targets exercise the primary untrusted byte boundaries for vault
container parsing.

---

## OTP / URI parsing

| Target                      | Purpose                              |
|-----------------------------|--------------------------------------|
| `parse_totp_otpauth_uri`    | otpauth:// URI parsing               |
| `import_interop_quarantine` | tolerant OTP import parsing          |
| `otpauth_roundtrip`         | encode/decode roundtrip verification |

These targets validate URI parsing logic and interoperability handling.

---

## Encoding / canonicalization

| Target                           | Purpose                            |
|----------------------------------|------------------------------------|
| `decode_base32_secret_strict`    | strict Base32 decoding             |
| `canonicalize_base32_for_export` | Base32 canonicalization for export |

These targets validate Base32 input normalization and decoding safety.

---

## Vault operations

| Target                   | Purpose                                 |
|--------------------------|-----------------------------------------|
| `vault_codec_roundtrip`  | vault encode/decode roundtrip           |
| `enable_duress_on_vault` | legacy vault → duress-enabled migration |

`enable_duress_on_vault` is intentionally **slow** because it performs
Argon2id key derivation and multiple cryptographic operations.
---

## Structure-aware targets

| Target                              | Purpose                                  |
|-------------------------------------|------------------------------------------|
| `parse_totp_otpauth_uri_structured` | protocol-shaped OTPAuth URI parsing      |
| `otpauth_roundtrip_structured`      | semantic OTPAuth roundtrip validation    |
| `vault_codec_roundtrip_structured`  | structured vault encode/decode roundtrip |
| `enable_duress_on_vault_structured` | structured duress migration validation   |

These targets complement byte-level fuzzing and do not replace hard
boundary fuzz targets.

# Running Fuzzing

All fuzzing is orchestrated through:

```bash
scripts/run_fuzz.sh
```

## Run fuzzing

Run a fuzz campaign:

```bash
./scripts/run_fuzz.sh run <seconds>
```

> Example:
> ```bash
> ./scripts/run_fuzz.sh run 60
> ```

---

## Run corpus minimization

Reduce corpus size while preserving coverage:

```bash
./scripts/run_fuzz.sh min
```

---

## Run fuzz + minimization

Typical workflow:

```bash
./scripts/run_fuzz.sh all 60
```

This will:

1. run fuzzing for each target
2. minimize the generated corpus
3. update `corpus_min`

---

# Corpus Layout

```md
fuzz/
├── corpus_seed/ curated manual seeds
├── corpus/ runtime corpus generated by fuzzing
├── corpus_min/ minimized corpus
├── artifacts/ crash inputs generated by libFuzzer
└── logs/ fuzz execution logs
```

### corpus_seed

Manually curated high-value inputs used to bootstrap fuzzing.
> These are stable and version-controlled

### corpus

Runtime corpus generated by fuzzing runs.
> Not version-controlled

### corpus_min

Minimized corpus produced by `cargo fuzz cmin`.
> Not required for version control

### artifacts

Crash inputs produced by libFuzzer.
> These should be investigated immediately

---

# Seed Promotion

Occasionally inputs from `corpus_min` may be promoted into
`corpus_seed` if they provide meaningful semantic coverage.

Typical promotion criteria:

- structured inputs that reach deep parsing states
- inputs that cover important protocol boundaries
- inputs exercising edge cases not covered by manual seeds

Promotion is done by copying files from:
`corpus_min/<target>/` to `corpus_seed/<target>/`
with a *semantic filename*.

---

# Crash Handling

If a crash occurs, libFuzzer will write the input to `fuzz/artifacts/<target>/`.

To reproduce:

```bash
cargo +nightly fuzz run <target> fuzz/artifacts/<target>/<artifact>
```

To minimize the crashing input:

```bash
cargo +nightly fuzz tmin <target> <artifact>
```

Crashes should be investigated and fixed immediately.

---

# Security Expectations

All fuzz targets must guarantee:

- no panic
- no abort
- no sanitizer violation
- no unbounded allocation
- no infinite loop

All parsing functions must return structured errors instead of crashing.

---

# Notes on Heavy Targets

`enable_duress_on_vault` performs Argon2id key derivation with the
production KDF parameters:

```sh
memory = 64 MiB
iterations = 3
lanes = 1
```

Because of this, the target is **computationally expensive** and executes
much fewer iterations per second than other fuzz targets.

> This is expected and not a fuzzing malfunction

---

# Recommended Workflow

Typical fuzz development loop:

1. run fuzz campaign
2. inspect logs
3. minimize corpus
4. promote useful seeds
5. repeat

For large campaigns, fuzzing should be executed through CI or scheduled
jobs instead of local development machines.

---

# Toolchain

Fuzzing requires nightly Rust and LLVM sanitizer support.

Install:

```bash
rustup toolchain install nightly
cargo install cargo-fuzz
```

Verify:

```bash
cargo +nightly fuzz --help
```

---

# Disclaimer

Fuzzing significantly increases confidence in parser robustness but does
not guarantee the absence of vulnerabilities.
